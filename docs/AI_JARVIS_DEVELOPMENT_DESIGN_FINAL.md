# AI Jarvis 开发设计文档

版本：首期方案汇总版  
日期：2026-09-04

## 1. 文档目的

本文档定义 AI Jarvis 的首期产品目标、交互规则、运行状态、模型调度、课程记录、数据生命周期和验收标准。开发实现可以调整内部算法，但不得改变本文明确规定的用户行为、隐私边界和状态优先级。

## 2. 产品定义

AI Jarvis 是运行在 Windows 本地的多模态 AI 桌宠。它持续感知用户当前的屏幕和系统声音，在合适的时机提供陪伴、提醒和帮助。
产品遵循以下原则：

- 感知持续进行，模型只在计划时间或显著事件发生时调用。
- 游戏场景强调存在感和即时反馈，普通场景强调克制。
- 场景识别、课程会话和用户对话是不同状态，不相互替代。
- 屏幕、系统声音、麦克风、模型和个人数据默认只在本机处理。
- 用户可以立即暂停全部感知并管理本地数据。
- 产品只以文字回复，不提供语音合成。

## 3. 首期范围

### 3.1 包含能力

- 桌宠待机、互动、课程和隐私暂停动画。
- 游戏场景中的屏幕弹幕。
- 普通场景中的桌宠文字气泡。
- 屏幕动态采样、多帧程序过滤和模型动态调度。
- 系统声音感知和 SenseVoice-Small 转写。
- 用户主动开启的麦克风语音对话。
- 自动及手动课程记录。
- 图文课程重点笔记。
- 当前应用运行期间的短期对话上下文。
- 用户确认的长期记忆和每日活动总结。
- 本地数据查看、删除和隐私暂停。

### 3.2 首期不包含

- 云端推理和独立 Web 服务。
- 语音合成回复。
- 唤醒词和麦克风持续监听。
- 课程笔记正文编辑器。
- 完整课程录音和完整课程转写的长期保存。
- 多显示器专门适配。
- 对所有独占全屏或带反作弊保护的游戏保证弹幕覆盖兼容。
- 系统代替用户执行高风险操作。

## 4. 总体架构

项目采用 Tauri、Rust 和本地原生推理运行库协作的桌面架构。应用后端、调度、数据处理和模型编排统一使用 Rust。

```text
Tauri 界面
  ├─ 桌宠、气泡、弹幕、课程状态和设置
  └─ 用户文字输入、麦克风开关和课程开关

Rust 应用层
  ├─ 屏幕采集、系统音频采集和麦克风采集
  ├─ 多帧过滤、环形缓冲、定时器和状态机
  ├─ Qwen 提示词和上下文组装
  ├─ SenseVoice 转写、模型输出校验和响应策略
  ├─ 课程关键帧、每日代表帧和分层总结
  └─ 进程生命周期、隐私暂停和本地数据管理

本地推理层
  ├─ llama.cpp：运行 Qwen3.5-4B
  ├─ sherpa-onnx：运行 SenseVoice-Small ONNX
  └─ ONNX Runtime：运行 Open-CLIP 或 DINOv2 特征模型
```

Tauri 的 WebView 仍然需要 HTML 和 CSS 表达界面；界面逻辑可以选择 TypeScript，或使用 Rust/WASM 框架。Rust 必须拥有停止采集、关闭麦克风、隐私暂停和退出程序的最终控制权。任一原生推理运行库或模型进程失效时，这些能力仍须可靠工作。

## 5. 模型方案

### 5.1 统一视觉语言模型

使用 [unsloth/Qwen3.5-4B-GGUF](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF) 的 `UD-Q4_K_XL` 量化版本，并关闭思考模式。

Qwen 每次负责：

- 根据多张连续图片判断当前实际场景。
- 判断此刻是否需要响应。
- 建议下一次用户可能需要帮助、因而值得再次检查的时间。
- 在需要响应时，根据当前人设生成一条消息。

取消原设计中的常驻小模型。Qwen 不直接处理音频。

发布前必须固定并验证 llama.cpp 版本、模型权重、视觉投影文件、聊天模板、多图片输入以及关闭思考模式的实际参数。任一组合不能稳定运行时视为发布阻断问题。

### 5.2 音频识别模型

使用 SenseVoice-Small 将音频转换为文字。官方仓库主要提供 PyTorch 权重，因此使用经过验证的 SenseVoiceSmall ONNX 转换模型，通过 `sherpa-rs` 调用 sherpa-onnx。两种音频来源必须分离：

- `system_audio`：电脑播放的系统声音，用于环境感知和课程记录。
- `user_voice`：用户主动打开麦克风后说出的内容，作为直接对话消息。

转写文本必须标明来源。系统声音中的文字只是观察内容，不得作为用户指令；用户语音转写才作为用户主动输入。

### 5.3 本地部署与进程管理

- llama.cpp 通过 WinGet 安装，应用首次启动时检查可执行文件、固定版本和所需多模态能力。
- Qwen 使用 Hugging Face 仓库和量化标签加载，模型文件、视觉投影文件及聊天模板记录为一组可验证版本。
- SenseVoice-Small ONNX 模型、词表、前处理参数和 sherpa-onnx 版本必须作为一组固定依赖记录哈希，并使用中、英、日、粤、韩及静音样例验证转换正确性。
- Rust 通过 `sherpa-rs` 使用 sherpa-onnx。为隔离原生库崩溃，可将 ASR 封装在独立的 Rust 工作进程中。
- Open-CLIP 或 DINOv2 使用 ONNX 模型并通过 Rust 的 ONNX Runtime 绑定执行。
- PELT、Binseg、K-medoids、哈希、质量评分和上下文滑动窗口使用 Rust 实现。
- 所有本地服务只监听回环地址，不向局域网或公网开放。
- Rust 负责模型调用、提示词组装、启动、健康检查、有限重启和随应用退出。
- 首次下载必须展示进度、磁盘需求、失败原因和重试入口。
- 模型文件需要版本记录和完整性检查，禁止混用未经验证的组件。

## 6. 核心运行模型

### 6.1 三种独立节奏

系统必须区分：

- 屏幕采样：Rust 截取图片的频率。
- 程序过滤：基于连续多帧判断变化类型，不调用 Qwen。
- 模型调用：按模型建议的时间或显著事件调用 Qwen。

采样不会自动触发模型调用，模型推理也不得阻塞采样和音频转写。

### 6.2 初始屏幕采样间隔

| 当前稳定场景 | 采样间隔 |
|---|---:|
| 游戏 | 3 秒 |
| 课程、普通视频、会议 | 6 秒 |
| 编码、办公、聊天、阅读 | 10 秒 |
| 其他有效画面 | 10 秒 |

上述数值是首期默认值，可在真机测试后调整。`active_session=course` 时始终使用 6 秒课程采样间隔，即使 `observed_scene` 暂时变为聊天、阅读或游戏，以保证课程活动记录连续。锁屏、息屏、系统睡眠、黑屏或无法取得有效画面时停止常规分析。

### 6.3 多帧缓冲与程序过滤

程序维护按采集顺序排列的屏幕帧环形缓冲。每次调用 Qwen 时传入最近 5 至 8 张有效图片，只说明图片按时间从早到晚排列，不附加采集时间。最后一张图片表示当前状态，前面的图片用于理解事件经过。

程序过滤同样基于多张连续图片，至少区分：

- `stable`：画面基本稳定。
- `continuous_motion`：游戏或视频中的持续运动。
- `transition`：加载、切换或动画过渡。
- `new_stable_state`：变化后形成了新的稳定状态。

普通持续运动不提前触发 Qwen。前台应用切换、锁屏状态变化、稳定画面后的突变以及新的稳定状态可以成为显著事件。

“有效变化”不能使用像素完全相等判断。应结合感知哈希、变化区域比例和连续多帧结果，忽略鼠标闪烁、系统时钟和局部小动画。

### 6.4 模型调用调度

Qwen 输出 `next_check_seconds`，表示：

> 从现在起经过多少秒，用户下一次可能需要帮助、提醒或陪伴，因此系统应再次调用模型观察和判断。

取值必须是 5 至 18 之间的整数。游戏和快速变化场景倾向较短，稳定工作和阅读倾向较长。较短间隔不代表本轮或下一轮必须回复。

调度规则如下：

- `next_check_seconds` 是下一次常规调用的最晚等待时间。
- 如果程序提前检测到显著事件，在满足调用下限后立即调用。
- 相邻两次普通调用至少间隔 5 秒。
- 5 秒内发生的多个事件合并，只提交最新状态和必要上下文。
- Qwen 正在推理时不并行发起新的 Qwen 请求。
- 推理期间只保留一个待处理事件标记；完成后根据最新状态决定是否补充调用。
- 课程候选状态的二次确认是唯一的 2 秒调用例外。

### 6.5 模型输出协议

Qwen 只返回一个合法 JSON 对象，不输出置信度、触发原因、Markdown 或额外字段。

```json
{
  "scene": "game",
  "need_response": true,
  "next_check_seconds": 5,
  "message": "这波走位很漂亮！\n差一点就翻车了。\n稳住节奏！"
}
```

字段规则：

- `scene`：当前屏幕的实际场景。
- `need_response`：本轮是否展示响应。
- `next_check_seconds`：5 至 18 的整数。
- `message`：始终只有一个字符串；无需响应时为空字符串。

游戏场景需要响应时，`message` 包含 3 至 5 行弹幕，以换行分隔。其他场景通常只生成一条适合气泡显示的短消息。

程序必须校验字段、枚举、时间范围和消息内容。解析失败时不展示内容，使用当前场景默认调用间隔，且不得无限重试。

### 6.6 场景枚举

模型场景限定为：

- `game`
- `course`
- `meeting`
- `video`
- `coding`
- `reading`
- `work`
- `chat`
- `other`

`scene` 只描述当前屏幕实际显示的内容。只要当前画面不是网课或教学内容，就必须判为非 `course` 场景。即使用户仍处于课程会话，PDF、笔记软件、搜索页面、聊天或游戏也按其实际内容分类。

锁屏、息屏和睡眠属于程序检测的不可交互状态，不属于模型场景。

## 7. 人设与对话上下文

### 7.1 人设

- 用户可以创建、编辑和管理多个人设。
- 每次启动时选择一个人设。
- 应用启动后不可更换人设。
- 人设提示词只影响 Qwen 的消息语气、措辞和性格。
- 人设不得改变场景判断、调用时间、隐私规则或 JSON 协议。

### 7.2 短期对话上下文

文字输入和用户语音输入共享当前运行期间的短期聊天上下文，以支持连续追问。应用退出后该短期上下文不继续保留。

上下文管理规则：

- 使用模型实际 tokenizer 计算文本上下文占用。
- 系统提示词、人设、输出协议和当前运行状态为固定区，不参与淘汰。
- 对话历史达到可用上下文容量的 80% 时，从最早的完整对话轮次开始删除。
- 每次删除完整的“用户消息 + 桌宠回复”，不得只删除半个轮次。
- 删除到约 70% 后停止，为新输入、视觉 token 和模型输出保留空间。
- 只做滑动窗口丢弃，不额外生成长期对话摘要。

视觉输入和近期系统声音转写按本轮任务装配，不作为聊天历史永久累积。

## 8. 主动响应与静止状态

### 8.1 普通主动响应

模型可以在普通场景中选择沉默。适合响应的情况包括明确提醒、阶段进展、明显失误、值得鼓励的结果或其他具有情绪价值的时刻。屏幕变化本身不构成响应理由。

用户主动发送文字或语音时属于直接对话，必须回复，不再判断 `need_response`。

### 8.2 屏幕长期不变

普通场景中，屏幕连续 2 分钟没有有效变化时，程序以静止原因为 Qwen 发起一次调用，本轮必须生成询问、提醒或陪伴消息。

如果画面仍未变化：

1. 首次静止调用计为第 1 次。
2. 后续每次随机等待 45 至 120 秒再调用。
3. 静止状态最多调用 3 次。
4. 第 3 次后仍无变化则停止调用。
5. 发生有效画面变化后，计数清零并恢复正常调度。

锁屏、息屏、睡眠、黑屏或无法取得有效画面时不进行静止提醒。

课程画面即使连续 2 分钟不变，只要 SenseVoice 仍产生新的有效课程转写，就保持课程状态，不进入普通静止提醒流程。

## 9. 课程会话

### 9.1 场景与会话分离

系统分别维护：

- `observed_scene`：模型看到的当前实际场景。
- `active_session`：程序维护的当前任务会话，可为 `none` 或 `course`。

用户确认仍在上课后，`active_session` 保持为 `course`，但 `observed_scene` 仍必须如实记录聊天、阅读、游戏等当前画面。

### 9.2 自动开始

自动课程识别采用二次确认：

```text
第一次识别为 course
→ 进入 course_candidate
→ 2 秒后额外采集一张新画面
→ 再次调用 Qwen
→ 第二次仍为 course
→ 正式进入 course_active
```

规则如下：

- 2 秒确认调用不受普通 5 秒调用下限约束。
- 第二次调用必须包含新采集的画面，不能重复使用完全相同的输入。
- 第二次不是 `course`、输出无效或调用失败时，不启动课程。
- 系统声音使用默认 60 秒内存环形缓冲。课程确认后，将相关前置音频纳入转写，补回二次确认期间的内容。
- 正式确认前不创建持久课程记录。

课程开始后立即：

- 显示固定消息“上课啦上课啦”。
- 播放一次 `course.gif`，随后停留在 `course.png`。
- 点亮桌宠旁的课程开关。
- 开始保存正式课程转写和临时课程图片。

### 9.3 手动开始与结束

鼠标悬停在桌宠上时显示课程开关按钮：

- 用户打开课程开关时立即开始课程，不经过二次模型确认。
- 用户关闭时立即结束课程并启动后台笔记生成。
- 课程状态必须持续可见，不能只在鼠标悬停时显示。

### 9.4 切换到非课程画面

课程进行时，只要模型识别到当前画面不是 `course`，程序显示固定确认：

> 你还在上课吗？

选择“是”：

- 保持 `active_session=course`。
- 继续系统声音转写，并保持每 6 秒一次的课程屏幕记录。
- 保留真实的非课程 `observed_scene`。
- Qwen 可以根据当前活动提醒用户回到课程。
- PDF、笔记、课程搜索等也视为非课程画面，不自动豁免确认。

选择“否”：

- 结束课程会话。
- 切换到当前实际场景。
- 后台开始生成课程笔记。

30 秒没有选择时按课程结束处理。确认期间如果画面重新回到课程内容，则取消询问并继续课程。

### 9.5 课程画面停留但讲解停止

课程画面不变且连续 1 分钟没有新的有效转写时，程序显示固定确认：

> 课程结束了吗？

- 选择“是”：结束课程并生成笔记。
- 选择“否”：继续课程，并重新开始 1 分钟计时。
- 30 秒没有选择：自动退出课程状态。
- 询问期间出现新画面或新有效转写：取消询问并重新计时。

## 10. 课程数据与笔记

### 10.1 课程期间的数据

- 系统声音由 VAD 切成有限长度的语音段。
- SenseVoice 为每段生成带内部时间信息的临时转写。
- 原始音频在对应转写成功写入临时存储后立即删除。
- 转写失败时允许有限次数重试；失败后标记该片段缺失并删除音频。
- 课程屏幕按 6 秒间隔临时保存到课程工作目录。
- 敏感应用和排除区域始终不得进入课程图片或模型输入。

### 10.2 关键画面选择

课程关键画面采用“程序生成候选，模型结合内容筛选”的两阶段方案。

程序阶段：

1. 排除黑屏、纯色、模糊、加载动画和损坏图片。
2. 使用连续多帧 pHash、OCR 文本变化和画面结构识别翻页、板书变化、图表出现和应用切换。
3. 每组相似画面选择清晰度和完整度最高的一张。
4. 长时间不变时定期保留兜底候选，避免遗漏持续讲解的重要图表。
5. 将每张候选图与附近的 SenseVoice 转写绑定。

模型阶段：

1. 每批向 Qwen 提交 5 至 8 张候选图及对应转写。
2. 选择能够代表知识点、解释、例子、结论或课堂活动的图片。
3. 对各批次结果进行主题级合并。
4. 课程内容图片优先；非课程活动只保留少量能说明活动切换的代表图。

### 10.3 笔记结构

课程笔记以内容信息为主，以发生顺序为辅：

- 按知识主题组织章节，不按固定时间段机械切分。
- 关键图片插入对应知识点附近。
- 聊天、游戏、查资料等非课程画面按实际发生位置穿插在正文中。
- 非课程活动只作简短记录，不单独强调持续时间。
- 底层时间信息用于对齐转写和图片，正文不突出时间线。
- 中断后回到同一知识点时继续归入原主题。

生成后的课程笔记正文为只读内容，不提供应用内正文编辑功能。课程标题属于元数据，允许用户修正。

### 10.4 清理与恢复

课程结束后按以下顺序处理：

```text
临时转写和临时图片
→ 主题切分
→ 分批图文总结
→ 合并完整笔记
→ 校验并原子保存
→ 删除临时数据
```

最终长期保留：

- 课程笔记。
- 笔记实际引用的关键图片。
- 课程标题、创建时间和必要索引。

生成成功后删除：

- 完整 SenseVoice 转写。
- 未入选图片和缩略图。
- 中间摘要与临时索引。
- 所有原始音频。

只有最终笔记成功写入且能够重新读取后才能清理临时数据。生成失败、应用崩溃或设备断电时保留工作目录，重启后继续生成。用户删除课程时同时删除笔记、关键图片和索引。

## 11. 个人记忆

长期记忆只保存对未来交互确实有价值且经过用户确认的信息，例如明确偏好、长期任务背景和用户指定要记住的事项。

- 屏幕观察、模型推测、完整聊天和课程临时转写不得自动成为长期记忆。
- Qwen 可以提出记忆候选，但必须由用户确认后才写入。
- 用户可以查看、编辑、删除或关闭长期记忆。
- 长期记忆与当前运行期间的滑动对话窗口分开存储。
- 关闭记忆后停止生成和写入新候选，不影响用户主动删除已有内容。

## 12. 每日活动总结

### 12.1 正式活动帧

程序必须区分短时推理缓冲帧、课程临时图片和正式活动帧。短时缓冲帧不全部落盘；正式活动帧按活动记录策略保存，用于每日总结，并遵循用户配置的保留期限。

显著事件帧、用户主动标记内容和课程节点应获得更高保留优先级。被排除的应用、窗口和区域不得进入正式活动帧。

### 12.2 代表画面选择

每日总结在用户发起或计划时间到达后执行：

1. 按时间处理正式活动帧，使用 pHash 或 aHash 去除相邻近似画面。
2. 使用 Open-CLIP ViT-L/14 提取语义向量；需要强调页面结构时可补充 DINOv2 ViT-S/14。
3. 在按时间排列的向量序列上使用 PELT 检测活动切换点；数据较大时可使用 Binseg。
4. 对过长时段再次细分，不强制每天产生固定数量的时段。
5. 每个时段通常选择 1 至 2 张代表帧，复杂时最多 3 张。
6. 稳定时段选择中间画面，内容多样时使用 K-medoids 从实际图片中选代表图。
7. Qwen 先生成分段摘要，再按时间顺序合并为全天总结。

不得使用全局 K-means 切分一天，避免把早晚两次相似活动错误合并。每日总结应描述主要活动流转、重要事件以及学习或工作进展，不逐张复述截图。

### 12.3 数据控制

- 用户可以查看、删除和按日期管理正式活动帧与每日总结。
- 删除正式活动帧时同步删除特征向量、索引和无来源的派生内容。
- 生成总结失败不得伪造结果，也不得阻塞前台模型调用。
- 每日总结属于可延迟后台任务；资源不足时等待空闲再执行。

## 13. 用户文字与语音对话

### 13.1 文字对话

用户可通过桌宠界面输入文字。文字作为直接用户消息提交给 Qwen，模型必须回复，回复显示在桌宠气泡中。

### 13.2 语音对话

麦克风只在用户主动操作时开启：

```text
点击麦克风按钮
→ 开始录音并显示录音状态
→ 用户再次点击
→ 关闭麦克风
→ SenseVoice 转写
→ 立即作为用户消息发送给 Qwen
→ 删除临时麦克风音频
```

规则如下：

- 不使用唤醒词和自动静音结束。
- 不向用户显示、编辑或确认转写文字。
- `Esc` 取消本次输入并删除音频。
- 无有效转写时不调用 Qwen，显示固定提示“没听清，再说一次？”。
- 用户语音转写不进入课程笔记。
- 隐私暂停或程序退出时立即关闭麦克风并丢弃未提交音频。
- 模型回复仍为文字，不进行语音合成。

## 14. 桌宠状态与动画

现有素材映射：

| 素材 | 用途 |
|---|---|
| `idle.gif` / `idle.png` | 普通待机 |
| `normal.gif` / `normal.png` | 普通互动和文字气泡 |
| `course.gif` / `course.png` | 课程状态和课程互动 |
| `closed-eyes.gif` / `closed-eyes.png` | 屏蔽或隐私暂停 |

动画规则：

- GIF 一般只播放一次，不持续循环。
- GIF 播放完成后停留在对应 PNG。
- 新互动发生时，从 GIF 第一帧重新播放一次。
- 普通场景回复播放一次 `normal.gif`，随后回到待机静态图。
- 课程开始及课程中的回复播放一次 `course.gif`，气泡可同时显示，随后停留在 `course.png`。
- 隐私暂停播放一次 `closed-eyes.gif`，随后停留在 `closed-eyes.png`。
- 同一批游戏弹幕只触发一次普通互动动画。

素材画布尺寸不同。桌宠窗口应使用固定容器并将角色底部居中对齐，避免切换动画时出现位置和窗口尺寸跳动。WebView 重播相同 GIF 时必须显式重置到第一帧，不能依赖重复设置相同 URL。

状态优先级：

```text
隐私暂停 > 课程状态 > 普通互动 > 待机
```

隐私暂停后，即使旧模型请求随后返回，也不得显示消息或播放互动动画。

## 15. 游戏弹幕

游戏场景需要响应时，Qwen 在一个 `message` 字符串中生成 3 至 5 行短弹幕，以换行分隔。每行只表达一个意思，程序按 `\r?\n` 拆分；换行格式失效时可以按中文句号、问号和感叹号兜底分句。超过 5 条时只展示前 5 条。

弹幕展示规则：

- 第一条立即出现。
- 后续每条随机间隔 0.4 至 1.2 秒发射。
- 从屏幕右侧向左移动。
- 主要限制在可用屏幕顶部约 30% 的区域。
- 使用透明、置顶、鼠标穿透且不抢焦点的覆盖窗口。
- 根据字体高度划分固定轨道，并预估文字宽度和速度以避免碰撞。
- 没有安全轨道时短暂等待，不允许文字互相覆盖。
- 退出游戏、关闭弹幕或进入隐私暂停时，立即取消未发射及正在显示的弹幕。
- 首期不专门处理多显示器，弹幕始终显示在桌宠所在显示器。

普通场景使用桌宠旁气泡，不进入全屏弹幕轨道。

## 16. 本地数据与隐私

### 16.1 数据分类

- 模型和运行依赖。
- 短时屏幕帧与系统声音环形缓冲。
- 课程生成期间的临时转写和候选图片。
- 只读课程笔记及其关键图片。
- 正式活动帧、每日总结及其派生索引。
- 用户确认的长期记忆。
- 最小化的运行日志和诊断信息。

结构化元数据建议使用 SQLite，图片和临时媒体使用受控本地目录。数据库只保存文件引用，不存储大块图片二进制。课程笔记可保存为 Markdown 正文和本地图片引用，由 Tauri 安全渲染。

### 16.2 隐私暂停

隐私暂停必须立即停止：

- 新的屏幕采集。
- 新的系统声音采集与转写。
- 麦克风采集。
- 新的 Qwen 调用。
- 新的课程、活动和记忆写入。
- 桌宠气泡与游戏弹幕展示。

暂停状态在桌宠、托盘和设置中持续可见，并在应用重启后保持。暂停发生前已经在途的模型结果必须丢弃。

### 16.3 用户控制

- 屏幕感知、系统声音、主动响应和记忆分别提供开关。
- 麦克风仅由用户主动开启。
- 支持排除敏感应用、窗口和屏幕区域。
- 支持导出用户选择的笔记、总结、记忆和活动数据。
- 支持按日期、类别和全部范围删除数据。
- 删除覆盖原始文件、关键图片、笔记、索引、派生内容和缓存。
- 日志不得记录完整提示词、完整转写、原始音频或可还原的敏感画面。

### 16.4 设置与运行管理

设置界面至少提供屏幕感知、系统声音、主动响应和长期记忆的独立开关，以及课程记录状态、数据保留期限、模型下载与可用状态、磁盘和内存提示、开机启动、托盘行为和快捷键管理。采样间隔首期由场景策略统一控制，不向用户暴露逐场景数值调节。

## 17. 故障处理

- Qwen 不可用时停止主动响应，但桌宠、托盘、隐私暂停和数据管理保持可用。
- SenseVoice 不可用时停止依赖音频的记录，并明确标记课程内容缺少音频依据。
- 音频转写失败不得伪造文字。
- 课程总结失败时保留临时工作目录并支持重试。
- 模型进程反复退出时使用有上限的退避重启，达到阈值后停止自动重启。
- 本地存储异常时停止新增持久数据，保护已有数据可读。
- 采集权限撤销后立即停止相应采集并更新界面状态。
- 应用异常退出后，重启时先清理无归属的麦克风音频，再恢复可恢复的课程生成任务。

## 19. 验收标准

### 19.1 模型与调度

- Qwen 能稳定接受 5 至 8 张有序图片并输出可解析 JSON。
- `next_check_seconds` 始终为 5 至 18 的整数。
- 显著事件能够提前调用，但普通调用间隔不低于 5 秒。
- 模型推理期间采样和 SenseVoice 转写不中断。
- 游戏和视频中的持续运动不会造成失控调用。
- 对话上下文达到 80% 时能够按完整轮次滑动淘汰。

### 19.2 游戏体验

- 游戏回复可拆成 3 至 5 条弹幕。
- 弹幕以 0.4 至 1.2 秒随机间隔从右向左显示。
- 弹幕不重叠、不抢焦点、不阻断鼠标操作。
- 离开游戏或隐私暂停后弹幕立即清空。

### 19.3 课程体验

- 连续两次识别为课程后自动开始，第二次确认间隔为 2 秒且包含新画面。
- 课程开始时显示“上课啦上课啦”并播放课程动画。
- 非课程画面能触发“你还在上课吗？”确认，并按用户选择保持或结束课程。
- 课程静态画面但持续有有效转写时不会被误判为静止离开。
- 课程画面和转写同时静止 1 分钟后正确询问课程是否结束。
- 最终笔记以内容主题为主，关键图片与内容对应，并包含发生在课程会话中的非课程活动。
- 笔记成功后只保留最终笔记和引用图片。

### 19.4 隐私与数据

- 隐私暂停后不再产生屏幕、音频、模型调用、记录或消息展示。
- 麦克风只在用户主动开启期间采集。
- 系统声音不会被当作用户指令。
- 原始音频在转写完成后删除。
- 课程完整转写在最终笔记成功保存后删除。
- 正式活动帧能够按保留期限清理，每日总结仍保持引用一致性。
- 未经用户确认的模型推测不会写入长期记忆。
- 用户删除后相关文件、索引、派生内容和缓存均不可再从产品访问。

### 19.5 稳定性

- 长时间运行无持续内存增长和失控磁盘增长。
- 模型进程异常不会阻止隐私暂停和程序退出。
- 课程生成中断后可以恢复，且不会因提前清理而丢失全部材料。
- 前台办公、视频和游戏没有不可接受的卡顿。

| 参数 | 首期值 |

## 21. 完成标准

首个可用版本必须同时满足：

- 用户能够完成本地模型安装、检查和首次运行。
- 屏幕采样、程序过滤、动态模型调度和响应展示形成稳定闭环。
- 游戏弹幕能够提供具有固定人设的连续陪伴体验。
- 系统声音转写和用户麦克风对话来源隔离正确。
- 自动及手动课程记录能够生成可阅读的图文重点笔记。
- 用户确认的长期记忆和每日活动总结可以查看与删除。
- 桌宠状态、动画、气泡、弹幕和隐私暂停行为一致。
- 临时音频、完整转写和未采用课程图片按生命周期可靠删除。
- 长时间运行、异常恢复、资源占用和隐私验收达到发布要求。
